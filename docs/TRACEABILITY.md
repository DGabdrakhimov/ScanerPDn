## Зафиксированные ограничения кандидата

1. Для уменьшения риска запросы с query пропускаются целиком. Это исключает сайты, где документы/страницы доступны только по параметрам. Статус partial и причина видны.
2. Флажки cookie, смысл политики и согласий отсутствуют в R1 согласно плану. Cookie — только заголовки реально полученных ответов страниц/документов; cookie из robots.txt не включаются в инвентаризацию.
3. Формы обнаруживаются после загрузки; предварительно расставить приоритет неизвестным страницам с формами невозможно. Приоритет явно подписанных документов реализован.
4. Расширенное сохранение исходных имён/path cookie и произвольных URL заменено консервативными хешами. Срок Expires сохраняется как нормализованная дата, не как произвольная строка.
5. Код 2 используется также при ошибке сохранения/повторного рендеринга, а не исключительно до сети. Это документированный контракт кандидата.
6. Отдельные факты C01/C06 остаются отдельными замечаниями: один относится к транспорту страницы, другой к конфигурации формы. Система не считает число правонарушений. Межстраничная агрегация одинаковых TLS-замечаний пока не выполнена.
7. Dockerfile использует tag базового образа, без digest; готового образа нет. Для воспроизводимого окончательного выпуска требуется проверенная сборка и фиксация digest.
8. Синтетические тесты созданы вместе с реализацией; это не независимый закрытый тестовый набор. Минимальное количество примеров соблюдено, статистическая точность не установлена.
9. JSON Schema приложена, но отдельный сторонний валидатор JSON Schema в среде не запускался. Встроенная проверка структуры применяется при рендеринге.
10. Назначен репозиторий DGabdrakhimov/ScanerPDn, ветка main. Исходная локальная история остаётся в bundle; сведения о публикации — docs/GIT.md.
