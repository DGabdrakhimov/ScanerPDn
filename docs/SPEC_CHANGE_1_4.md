# Спецификация 1.4 — изменение клиентского отчёта

Дата: 14.10.2026. Дополнение к спецификации 1.3.

## 41 Понятный клиентский отчёт R1

UI-01. HTML-отчёт предназначен для клиента без технической подготовки. Основные разделы: итог и полнота; замечания и действия; отдельные проверки; справочник правил; найденные элементы сайта; ограничения и пропуски. Статусы выводятся по-русски; технические коды доступны отдельно.

UI-02. Колонки проверки: код и название правила, адрес объекта, результат, объяснение результата. Объяснение раскрывает установленный факт или причину невозможности вывода, а не повторяет pass, fail или not_applicable. При доступности доказательств показывать ответы двух попыток, код ответа сервера, сетевую ошибку или неоднозначность разметки. Не восстанавливать отсутствующие сведения догадкой.

UI-03. Код и название ведут к справочнику C01–C07 ниже таблицы. Для каждого правила указать понятное название, проверяемое условие и границу достоверности. Например, непустой ответ не подтверждает достаточность текста политики, а отсутствие HTTP-адреса в форме не доказывает безопасность фактической передачи.

UI-04. В итогах отдельно показывать адреса и проверки. completed/planned — число применимых проверок с определённым исходом относительно всех применимых проверок; это не доля страниц или всего сайта. Для partial показывать сохранённые причины неопределённых результатов. Ноль пропущенных адресов не равен полноте всех правил.

UI-05. Названия статусов: pass — «Замечаний по правилу нет»; fail — «Обнаружено замечание»; not_applicable — «Не относится к этому объекту»; inconclusive — «Недостаточно данных»; not_checked — «Не проверено». Юридические статусы по разделу 25 не заменяются этими техническими результатами.

## 42 Представление найденных элементов

UI-06. Вместо JSON отображать отдельные таблицы документов, форм, cookie и внешних доменов. Машиночитаемый report.json сохраняется. Пустые списки объяснять как отсутствие находок в обследованном объёме, а не как доказательство отсутствия элемента на всём сайте.

Документы: подпись или «возможный документ», адрес, страница обнаружения, способ распознавания. Отличать явную подпись от предположения по адресу. Доступность ссылки не подменяет оценку содержания документа.

Формы: страница, номер формы на странице, типы и количество элементов, указанные адреса отправки, отметка «не отправлялась». Не сохранять введённые значения. Флажок выбора не считается подтверждённым согласием.

Cookie: безопасное имя или замаскированный идентификатор, источник, объявленный срок и понятные пояснения атрибутов. Не определять назначение по догадке. Cookie из сценариев JavaScript остаются вне R1.

Внешние домены: домен и факт упоминания в разметке. Не называть упоминание доказанной передачей персональных данных или трансграничной передачей.

UI-07. HTML автономный, без JavaScript и внешних ресурсов. Экранировать все значения из JSON, включая неизвестные коды и подписи. Не превращать замаскированные адреса в ссылки для открытия. Таблицы должны читаться на узком экране с горизонтальной прокруткой внутри таблицы; печать — с повторяемыми заголовками.

## 43 Совместимость и приёмка обновления

UI-08. Команда render должна переоформлять отчёты схемы 1.0 без сетевых запросов и изменения исходного JSON. Сохранять исходную версию сканера и отдельно указывать версию оформления. Если старый отчёт не содержит контекста, объяснять ограничение, а не добавлять новые результаты или правовые основания.

UI-09. Проверить успешный исход, замечание, неприменимость, неполные данные, неизвестный код, ошибки сети, ответы 403/404/429/5xx, пустую и заполненную инвентаризацию, экранирование HTML и старые отчёты. Итоговые числа, цвет, исходы и доказательства не должны изменяться при переоформлении.

Выпуск 0.1.0rc2 от 14.10.2026 — обновление представления отчёта на базе 0.1.0rc1. Семь алгоритмов сканирования и схема JSON 1.0 сохранены; в новые checks добавлены необязательные поля object_kind и message. Это не заявление о выполнении всех требований спецификации 1.4: нормативный каталог и правовые блоки версии 1.2 остаются отдельной незавершённой доработкой. Содержание документов и сверка РКН сохраняются в R2.1/R2.2.

По предоставленному пользователем журналу 14.10.2026 версия rc1 установлена и выполнила запуск в WSL с Python 3.14.4: 45 запросов, 19 посещённых уникальных адресов, 49 определённых результатов из 61 применимой проверки, статус partial. Это подтверждает один запуск, но не полную совместимость Python 3.14 и не результаты приёмочного пилота. Сам report.json в рамках этого сообщения не предоставлен; конкретные причины неопределённых проверок по консольной сводке не устанавливаются.

Разделы 41–43 изменяют требования к представлению и совместимости. Нормативные ссылки предыдущих разделов сохранены; новая правовая экспертиза законодательства этим изменением не заявляется.
