# PDScan 0.1.0rc1 — консольный сканер сайтов

Первый работающий кандидат в выпуск R1 по спецификации v1.1 от 07.10.2026.
Только HTTP и статический HTML: **без сайта сервиса, регистрации, API-ключа, LLM и подтверждения экспертом**.
Дата выпуска: 09.10.2026. Язык отчёта — русский.

**Статус: release candidate, не окончательно принятый R1.** Автоматические тесты и установка проверены на Linux/Python 3.12.14. Пилот на 10 разрешённых публичных сайтах, WSL2 и сборка/запуск Docker ещё не выполнены. Прямой выход к example.org в среде разработки завершился DNS-ошибкой; сканер вернул серый частичный отчёт. Не заявляем 99% точности на реальных сайтах.

## Репозиторий и установка из исходников

Репозиторий: https://github.com/DGabdrakhimov/ScanerPDn, ветка `main`.

```bash
git clone https://github.com/DGabdrakhimov/ScanerPDn.git
cd ScanerPDn
python3 -m venv .venv
source .venv/bin/activate
python -m pip install .
pdscan doctor
```

Эта установка получает инструменты сборки из pyproject.toml. Для установки без сети используйте wheel из ZIP-пакета, как описано ниже. Перед сборкой Docker из Git checkout создайте wheel: `python -m pip wheel --no-deps . -w dist`.

## Быстрый запуск: Linux или Ubuntu в WSL2

Распакуйте ZIP и перейдите в каталог `pdscan-0.1.0rc1`.
Нужен Python 3.11 или новее с модулем venv; проверена версия 3.12.14.
Для Ubuntu, если Python/venv отсутствуют: `sudo apt install python3 python3-venv`.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --no-index dist/pdscan-0.1.0rc1-py3-none-any.whl
pdscan --version
pdscan doctor
pdscan scan https://ВАШ-ДОМЕН/ --output ./reports/first
```

Замените `ВАШ-ДОМЕН` на домен сайта, который разрешено проверять. Не вводите адрес с логином, паролем или токеном.
Wheel устанавливается без доступа к PyPI: сторонних зависимостей времени выполнения нет.
На WSL2 рекомендуется хранить код и окружение внутри Linux (`~/projects/pdscan`), а не в каталоге синхронизации Windows.

Результат — `reports/first/report.html`. Откройте файл браузером (например, через проводник WSL: `explorer.exe reports/first`). HTTP-сервер для просмотра не нужен.
Повторный запуск пишите в новый каталог. После завершения можно закрыть терминал: файлы отчёта остаются на диске.

## Режимы и команды

| Команда | Назначение |
|---|---|
| `pdscan scan URL --output DIR` | Две попытки на объект, ограниченный обход одного сайта |
| `pdscan scan URL --config examples/scan.toml --output DIR` | Настройка лимитов и области через TOML |
| `pdscan render DIR/report.json --output DIR/copy.html` | Пересоздание HTML без сети |
| `pdscan rules list` | Каталог семи правил, ключи и рекомендации |
| `pdscan doctor --output .` | Python, TLS, доверенные сертификаты, запись в каталог; без сканирования |
| `pdscan --help` / `pdscan scan --help` | Справка |

```bash
# Только начальная HTML-страница + обнаруженные явно обозначенные документы:
pdscan scan https://ВАШ-ДОМЕН/ --max-pages 1 --max-depth 0 --output reports/single

# Явно разрешить www; сканер не расширяет область автоматически:
pdscan scan https://ВАШ-ДОМЕН/ --allow-host www.ВАШ-ДОМЕН --output reports/with-www

# Внешние документы: по умолчанию только инвентаризация, опция разрешает GET:
pdscan scan https://ВАШ-ДОМЕН/ --check-external-docs --output reports/external-docs

# Для автоматизированного вызова: stdout JSON, stderr прогресс:
pdscan scan https://ВАШ-ДОМЕН/ --output reports/job --quiet
code=$?
printf 'Код завершения: %s\n' "$code"
```

`--max-depth 0` не означает «полный сайт проверен»: остальные найденные страницы отмечаются как пропущенные, общий статус может быть partial.
`--max-pages` ограничивает страницы обхода; запросы документов, robots.txt, повторы и редиректы входят в общий `--max-requests`.
Отдельного агрессивного, внутреннего, аутентифицированного или браузерного режима в R1 нет.

Флаги: `--max-pages`, `--max-depth`, `--max-requests`, `--max-redirects`, `--time-limit`, `--timeout`, `--allow-host` (повторяемый), `--exclude-path` (повторяемый), `--check-external-docs`, `--quiet`, `--no-color`, `--stdout json|path`, `--overwrite`.
CLI имеет приоритет над TOML; повторяемые значения CLI заменяют соответствующий список TOML.
Вывод не использует ANSI-последовательности; `--no-color` поддерживается для совместимости.
`--overwrite` разрешён только для каталога с manifest.json от предыдущего запуска PDScan. Предпочтительно использовать новый каталог.

## Проверки

| ID | Воспроизводимый факт | Цвет |
|---|---|---|
| C01 | Конечный HTML получен по HTTP; наличие формы email/tel/password усиливает технический риск | Жёлтый / красный |
| C02 | Повторяется ошибка проверки срока, имени или доверия сертификату в окружении сканера | Красный |
| C03 | Явно обозначенная ссылка на политику/согласие дважды возвращает одинаковый 404 либо 410 | Жёлтый |
| C04 | Для такой ссылки повторяется один и тот же замкнутый цикл редиректов | Жёлтый |
| C05 | В подтверждённой цепочке документа есть HTTPS → HTTP | Жёлтый |
| C06 | В статическом HTML у типизированной формы указан HTTP action/formaction | Жёлтый |
| C07 | Документ поддержанного MIME дважды возвращает 200 с телом длины 0 | Жёлтый |

Точное распознавание четырёх подписей документов описано в `docs/RULES.md`.
Отсутствие распознанной подписи, cookie-баннера или checkbox **не объявляется нарушением**.
Формы не отправляются. Настоящая передача данных, JavaScript, содержание документов и серверные процессы не оцениваются.
Результаты не устанавливают нарушение 152-ФЗ, не определяют соответствие приказам ФСТЭК, не считают штрафы.

Красный/жёлтый обозначают технические замечания. Серый — неполнота или неоднозначность. Зелёный — отсутствие дефектов в выполненных технических проверках, а не соответствие закону.
При наличии замечания сводный цвет сохраняется, даже если проверка частичная; рядом всегда видны статус и покрытие.

## Коды завершения

- `0`: завершено без технических замечаний;
- `1`: завершено с замечаниями;
- `2`: ошибка конфигурации, окружения или сохранения результата;
- `3`: неполная проверка; найденные замечания при этом сохраняются;
- `130`: Ctrl+C; если отмена произошла при сканировании, сохраняется частичный отчёт.

В shell с `set -e` коды 1/3 могут прервать ваш сценарий. Обрабатывайте их как результаты сканирования.
Код 2 при сохранении отличается от проектного «только до сети»: отдельный код ошибки вывода не вводился, см. `docs/TRACEABILITY.md`.

## Файлы результата

- `report.json`: версии схемы/правил, замечания, все исходы, инвентаризация, покрытие и ограничения;
- `report.html`: автономный экранированный отчёт без JS и внешних ресурсов;
- `manifest.json`: конфигурация, время, метрики, хеши доказательств;
- `evidence/*.json`: очищенные минимальные наблюдения с SHA-256;
- `sanitized.log`: итоговый статус и число запросов.

Новые каталоги создаются с правами 0700, файлы — 0600 (действуют ограничения файловой системы/umask).
Полные страницы, значения полей, cookie и query-параметров не сохраняются. Нестандартные сегменты URL и имена полей заменяются хешами; host сохраняется. Хеширование не является юридически гарантированным обезличиванием. Отчёты могут содержать чувствительные сведения о структуре сайта — хранение и удаление контролирует пользователь.
Повторное использование каталога может оставить старые evidence-файлы, не включённые в новый manifest; для чистого отчёта создайте новый каталог.

## Ограничения и безопасность

По умолчанию: 30 страниц, глубина 2, 100 GET-запросов, 300 секунд, 10 секунд на запрос; 1 запрос/сек на host, без параллельного обхода.
Проверяются все адреса DNS, соединение закрепляется за проверенным IP, сверяется peer, для HTTPS сохраняется имя SNI и обязательная проверка сертификата. Частные/локальные адреса и порты кроме HTTP:80 / HTTPS:443 запрещены. Флага обхода нет.
Прокси из окружения игнорируются. Если сеть требует прокси, R1 в ней работать не будет; не отключайте защиту.
Запросы с query целиком пропускаются. Это намеренное сужение области, снижающее риск действий через GET. Явные logout/delete/unsubscribe и заданные исключения также не посещаются.
robots.txt учитывается; неопределённость о разрешениях останавливает соответствующий обход. WAF/CAPTCHA/авторизацию сканер не обходит.
Поддерживаются gzip/deflate с лимитами после распаковки; brotli и другие кодировки дают неполный результат.
Подписи, формы и атрибуты определяются по исходному HTML. Некорректная разметка и SPA ограничивают достоверность — результат может быть серым.

## Docker (рецепт; сборка ещё не проверена)

```bash
docker build -t pdscan:0.1.0rc1 .
mkdir -p reports
# Каталог должен быть доступен для записи указанному UID/GID.
docker run --rm --read-only --cap-drop=ALL --security-opt=no-new-privileges \
  --user "$(id -u):$(id -g)" \
  -v "$PWD/reports:/reports" pdscan:0.1.0rc1 \
  scan https://ВАШ-ДОМЕН/ --output /reports/run01
```

Не монтируйте домашний каталог, ключи SSH, Docker socket. Порты не публикуются.
Образ не приложен: Docker daemon в среде разработки недоступен. В архиве wheel и Dockerfile. Базовый tag не фиксирует digest; перед продуктивным выпуском закрепите проверенный digest и проведите повторную сборку.

## Разработка и тесты

```bash
PYTHONPATH=src python3 -m unittest discover -s tests -v
PYTHONPATH=src python3 tools/demo.py --output reports/demo
# Сборка из исходников в окружении с инструментами из requirements.lock:
python -m pip wheel --no-deps --no-build-isolation . -w dist
```

`tools/demo.py` создаёт отчёт по синтетическим ответам без сети; это демонстрация, не проверка реального сайта.
Тестовые приватные ключи в `tests/fixtures/tls/TEST_ONLY_key.pem` специально созданы для тестового TLS-стенда и не являются рабочими секретами. Никогда не используйте их вне тестов.

В ZIP также включён `pdscan.bundle` — переносимый Git-репозиторий с коммитами и тегом кандидата. Восстановление и публикация: `docs/GIT.md`.
Изменения: `CHANGELOG.md`. Результаты проверки: `docs/TEST_REPORT.md`. Соответствие спецификации: `docs/TRACEABILITY.md`.
