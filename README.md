# PDScan R2 — 0.2.0rc1

Консольный сканер публичных сайтов. Сохраняет проверки R1 и добавляет браузерный этап R2. Интерфейс сайта для запуска пока не нужен.

**Это тестовый кандидат, не принятый стабильный релиз.** В среде сборки прошли 263 автоматических теста; один интеграционный тест Chromium пропущен из-за недоступного браузера. Установка Playwright выполнена, загрузка Chromium завершилась ошибкой повреждённого архива. Реальный браузерный прогон и совместимость с вашей WSL/Python 3.14.4 ещё нужно подтвердить. Полный статус: [docs/TEST_REPORT.md](docs/TEST_REPORT.md).

Сканер сообщает наблюдаемые технические факты. Цвет не является юридическим заключением. Нормативные ссылки и причины недостаточности доказательств показаны отдельно. Отсутствие checkbox или cookie-баннера само по себе не объявляется нарушением.

## 2. Где вводить команды

В Windows используются **два разных терминала**:

- **PowerShell** — только распаковка архива и запуск WSL в пункте 3.
- **Ubuntu / WSL, Bash** — все дальнейшие команды, начиная с пункта 4.

Не копируйте приглашение вида `denis@NOTEBOOK-FORS:~$` и префикс `(.venv)`: их выводит терминал. Копируйте только содержимое блоков команд. Выполняйте блоки по порядку; при ошибке сначала устраните её.

Новая версия сканера будет в отдельной папке. **Новую версию Linux устанавливать не надо**. Мы копируем файлы программы с диска Windows в уже имеющуюся домашнюю папку Linux. Старую папку R1 и её отчёты сохраняйте для сравнения.

## 3. Скачать и распаковать — PowerShell

Сохраните архив как `C:\Users\user\Downloads\pdscan-0.2.0rc1.zip`. Если браузер сохранил его в другую папку, исправьте путь в первой строке.

```powershell
$archive = 'C:\Users\user\Downloads\pdscan-0.2.0rc1.zip'
Expand-Archive -LiteralPath $archive -DestinationPath 'C:\pdscan-r2'
Get-ChildItem 'C:\pdscan-r2\pdscan-0.2.0rc1'
wsl
```

`$archive` — переменная PowerShell с путём к архиву. `Expand-Archive` распаковывает настоящий ZIP; открытая в Проводнике папка внутри ZIP ещё не является установленной программой. `-LiteralPath` трактует путь буквально. `-DestinationPath` задаёт место распаковки. `Get-ChildItem` показывает содержимое. `wsl` открывает Linux по умолчанию; если по умолчанию другая система, откройте вашу Ubuntu через меню Пуск.

Если каталог назначения уже содержит предыдущую распаковку, выберите другое имя каталога и используйте его далее. Не распаковывайте разные версии поверх друг друга.

## 4. Скопировать в домашнюю папку Linux — Bash

```bash
mkdir -p ~/projects
cp -r /mnt/c/pdscan-r2/pdscan-0.2.0rc1 ~/projects/
cd ~/projects/pdscan-0.2.0rc1
pwd
ls
python3 --version
```

| Команда или фрагмент | Объяснение |
|---|---|
| `mkdir -p ~/projects` | Создать папку проектов; `-p` разрешает уже существующую папку |
| `~` | Ваша домашняя папка Linux, например `/home/denis` |
| `/mnt/c/` | Диск `C:` Windows, видимый из WSL |
| `cp -r источник назначение` | Скопировать каталог и всё его содержимое; `-r` означает рекурсивное копирование |
| `cd путь` | Перейти в каталог; последующие относительные пути считаются от него |
| `pwd` | Показать текущий каталог |
| `ls` | Показать файлы в нём |
| `python3 --version` | Показать версию Python, ничего не устанавливая |

Нужен Python **3.11 или новее**. Автоматические проверки этого кандидата выполнены на Linux/Python 3.12.14. Ваша версия 3.14.4 соответствует минимальному требованию, но именно с ней браузерный адаптер ещё не проверен.

В каталоге должны быть `pyproject.toml`, `README.md`, `src`, `dist`. Если копия этой версии уже существует, не повторяйте `cp -r` вслепую: повторное копирование может создать вложенную папку. Продолжите из уже распакованного каталога либо выберите новый путь.

## 5. Создать окружение и установить PDScan

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --no-index dist/pdscan-0.2.0rc1-py3-none-any.whl
pdscan --version
pdscan doctor
```

**Виртуальное окружение** — отдельная папка с настройками Python и установленными библиотеками для одного проекта. Это не виртуальная машина и не ещё один Linux. Оно помогает не смешивать зависимости R1, R2 и других программ.

- `python3 -m venv .venv`: запустить модуль `venv` и создать окружение в `.venv` текущего каталога. `-m` означает «выполни модуль Python».
- `source .venv/bin/activate`: изменить настройки **текущего терминала**, чтобы `python`, `pip` и `pdscan` брались из этой папки. Обычно слева появляется `(.venv)`.
- `python -m pip install ...`: запустить установщик именно выбранного Python. `--no-index` запрещает поиск в сетевом каталоге: готовый wheel устанавливается из архива, для R1 сторонние библиотеки не нужны.
- `pdscan --version` должен вывести `0.2.0rc1`.
- `pdscan doctor` проверяет базовое окружение, сертификаты и возможность записи; сайт не сканирует.

Если `venv` сообщает, что `ensurepip` недоступен, в обычной Ubuntu установите компонент для вашей версии Python. Для системного Python Ubuntu обычно:

```bash
sudo apt update
sudo apt install python3-venv
```

После этого повторите создание окружения. Для отдельно установленного Python 3.14 может понадобиться его собственный пакет `venv`, а не пакет системного Python. Не переключайте Python внутри уже созданного окружения: создайте новое.

**Не вводите `sudo apt install <deb name>` для ошибки `pdscan not found`.** Это общая подсказка Ubuntu, она не знает наш пакет. Проверяйте активацию окружения и установку wheel.

## 6. Сначала проверить режим R1

```bash
report_r1="$PWD/reports/ifors-r1-$(date +%Y%m%d-%H%M%S)"
pdscan scan https://i.fors.ru/ --mode r1 --output "$report_r1" --stdout path
scan_code=$?
printf 'Код завершения: %s\n' "$scan_code"
printf 'Папка отчёта: %s\n' "$report_r1"
explorer.exe "$(wslpath -w "$report_r1")"
```

Откройте `report.html` в появившейся папке Проводника. До первого сканирования браузер устанавливать не обязательно.

Что означает синтаксис:

- `report_r1=...` присваивает переменную Bash. **Пробелы вокруг `=` не ставятся**, иначе оболочка воспримет имя как команду.
- `$PWD` подставляет текущий каталог. `$report_r1` подставляет сохранённый путь.
- `$(date +%Y%m%d-%H%M%S)` выполняет `date` и подставляет дату/время. Например `20261014-143025`. Новый каталог сохраняет каждый запуск отдельно.
- Двойные кавычки `"..."` оставляют путь одним аргументом даже при пробелах. Одинарные кавычки не раскрывают переменные; здесь они не подходят для `"$report_r1"`.
- `scan` — подкоманда сканирования; URL — адрес сайта; `--mode` и `--output` — именованные параметры с последующими значениями.
- `--stdout path` выводит в конце только путь к HTML. Без него итоговый JSON в консоли содержит также результаты проверок и нормативные ссылки.
- `$?` — код **предыдущей** команды. Поэтому `scan_code=$?` стоит сразу после `pdscan`, до `printf` и других команд.
- `printf` выводит текст; `%s` заменяется значением, `\n` переводит строку.
- `wslpath -w` переводит Linux-путь в Windows-путь; `explorer.exe` открывает его в Windows. Это работает только в WSL; в обычном Linux откройте файл браузером вручную.

## 7. Установить браузерные компоненты R2

В том же активированном окружении:

```bash
python -m pip install "playwright==1.64.0"
python -m playwright install --with-deps chromium
pdscan doctor --browser
```

Первая команда устанавливает библиотеку управления браузером. Вторая скачивает совместимый Chromium и устанавливает его системные зависимости; Ubuntu может запросить пароль `sudo`. Пароль при вводе не отображается. Запускать сам сканер от `root` не нужно. Библиотека Playwright и браузер — разные компоненты: успешный `pip install` ещё не означает, что Chromium установлен.

`doctor --browser` дополнительно пробует запустить и закрыть Chromium без перехода на сайт. Успешный ответ содержит `"ready": true`. При `false` сначала устраните ошибку установки. Обычный Chrome в Windows автоматически не используется: R2 запускает собственный Chromium внутри Linux.

Не отключайте проверку TLS ради загрузки браузера. При повреждённом архиве/сетевой ошибке проверьте доступ к источнику загрузки и повторите команду установки. Если нужна корпоративная настройка прокси/сертификата, согласуйте её с администратором. Ограничения сети установки и сети самого сканера различаются.

Официальная инструкция Playwright: https://playwright.dev/python/docs/browsers

## 8. Запустить совместную проверку R1 + R2

```bash
report_r2="$PWD/reports/ifors-r2-$(date +%Y%m%d-%H%M%S)"
pdscan scan https://i.fors.ru/ --mode combined --browser-pages 1 --browser-time-limit 180 --output "$report_r2" --stdout path
scan_code=$?
printf 'Код завершения: %s\n' "$scan_code"
explorer.exe "$(wslpath -w "$report_r2")"
```

Сначала выполняется R1, затем R2. Это один последовательный запуск, в котором доступны результаты обоих этапов. Самостоятельный запуск R1 из пункта 6 удобен для проверки окружения, но не обязателен перед каждым `combined`.

В папке результата:

- `report.html` — общий отчёт с C01–C07 и B01–B06;
- `report.json` — его машинные данные;
- `r1/report.html` и `r1/report.json` — отдельно сохранённый HTTP-этап этого же запуска;
- `evidence/` — обезличенные структурированные наблюдения;
- `manifest.json` — версии, настройки, перечень материалов;
- `sanitized.log` — краткий технический журнал.

Если Chromium не запускается или превышает срок, общий результат будет частичным, R1 останется доступен. Сначала сохраняется отчёт R1, поэтому при аварийном завершении всего процесса проверяйте также корневой `report.html`. Во время работы браузера корневой отчёт ещё содержит промежуточный R1.

## 9. Режимы и лимиты

| Параметр | По умолчанию | Значение |
|---|---:|---|
| `--mode r1` | Да | Только HTTP/HTML; Chromium не нужен |
| `--mode combined` | Нет | R1, затем браузерный этап |
| `--max-pages` | 30 | Лимит страниц HTTP-обхода |
| `--max-depth` | 2 | Глубина переходов HTTP-обхода |
| `--max-requests` | 100 | Лимит HTTP-запросов R1, включая повторы и служебные запросы |
| `--time-limit` | 300 | Бюджет R1 в секундах |
| `--timeout` | 10 | Таймаут сетевого запроса |
| `--browser-pages` | 1 | Первые обнаруженные страницы для R2, допустимо 1–5 |
| `--browser-wait-ms` | 1500 | Ожидание после загрузки/действия, 100–5000 мс |
| `--browser-max-requests` | 150 | Общий бюджет сетевого транспорта R2, 8–1000 |
| `--browser-time-limit` | 180 | Бюджет R2, 10–1800 секунд; процесс принудительно останавливается после бюджета + 30 секунд |
| `--allow-host example.org` | Нет | Дополнительно разрешить точный хост; повторяется для нескольких хостов |
| `--exclude-path /account` | Нет | Исключить путь; повторяемый параметр |
| `--check-external-docs` | Нет | Проверка внешних явно подписанных документов только этапом R1 |
| `--quiet` | Нет | Скрыть сообщения прогресса, итог остаётся |
| `--config examples/scan.toml` | Нет | Загрузить параметры R1 из TOML; параметры команды приоритетнее |

Бюджеты R1 и R2 независимы. Их время складывается; к нему добавляются запуск и сохранение. Увеличение числа страниц без увеличения бюджета R2 может дать больше неполных сценариев. Прокси из переменных окружения сканер игнорирует; доступен только публичный HTTP/HTTPS на стандартных портах. `localhost` и внутренние IP запрещены. Локальное размещение самой программы поддерживается; сканирование внутренних сайтов — отдельный будущий режим.

Подробная справка:

```bash
pdscan --help
pdscan scan --help
pdscan rules list
```

Не используйте `--overwrite` для обычных запусков: новый каталог проще и безопаснее. Этот флаг допускает замену файлов распознанного отчёта PDScan, но не удаляет произвольную папку рекурсивно.

## 10. Что именно делает R2

| Сценарий | Действия в новом чистом контексте |
|---|---|
| S0 | Загрузить страницу без выбора |
| S1 | Найти однозначную кнопку отказа, нажать, наблюдать |
| S2 | Найти однозначную кнопку принятия, нажать, наблюдать |
| S3 | Принять, затем отозвать в том же контексте; сохранить оба состояния |

Каждый сценарий повторяется дважды. На одну страницу приходится до восьми загрузок. Это не ваш личный браузер: пароли, вход в аккаунт и сохранённые cookie пользователя не используются.

Автоматическое нажатие поддерживается только для единственной видимой активной `button type="button"` вне формы, внутри контейнера cookie или диалога с текстом cookie/куки. Поддержаны точные подписи (без учёта регистра и лишних пробелов):

- отказ: «Отклонить все», «Отказаться от всех», `Reject all`;
- согласие: «Принять все», «Разрешить все», `Accept all`;
- отзыв: «Отозвать согласие», «Отозвать согласие на cookie», `Withdraw consent`, `Withdraw cookie consent`.

Другие кнопки, несколько совпадений, вложенные настройки, ссылки вместо кнопок, закрытый shadow DOM — **не поддержаны**, а не «нарушение». Формы не отправляются, поля не заполняются. Запросы кроме GET, URL с query, внешние хосты вне разрешённой области, WebSocket и workers блокируются. Поэтому большинство сложных сайтов могут дать частичный результат.

R2 наблюдает отображаемые checkbox/radio и ARIA checkbox/switch, связанные подписи и ссылки; выполняет ограниченное распознавание формулировок. Снимки — структурированные признаки DOM, а не скриншоты. Cookie и localStorage сохраняются только как метаданные и хеши имён, без значений. Cookie не пересылаются обратно серверу; серверные сессии не воспроизводятся. Заголовки ответа воспроизводятся частично. Это ограниченный исследовательский режим, а не точная копия обычного посещения.

## 11. Как читать отчёт и код завершения

| Код | Значение |
|---:|---|
| 0 | Все запланированные применимые проверки определены, технических замечаний нет |
| 1 | Проверка завершена, есть технические замечания |
| 2 | Ошибка параметров, установки, чтения или сохранения; смотрите консоль |
| 3 | Проверка частичная; возможны и замечания, и непроверенные объекты |
| 130 | Остановка пользователем, например Ctrl+C |

Сначала прочитайте итог и причины неполноты. Затем замечания, результаты отдельных правил и справочник кодов. В R2 дополнительно есть сценарии, запросы, состояния выбора и cookie. «Ответ получен» не означает «переданы персональные данные», а «заблокировано» означает попытку запроса, остановленную сканером.

**Правовой статус** отдельно от технического: «Недостаточно данных» или «Не проверено». Ссылки на статью/часть/пункт показывают относящуюся норму и условие применимости, а не автоматически доказанное нарушение. Предустановленный checkbox — повод проверить конкретное согласие, но не готовая квалификация по КоАП.

Адреса вида `https://i.fors.ru/sha256:...` — **замаскированные идентификаторы, не ссылки для открытия**. Это объяснение теперь указано в отчёте. Хеш нельзя превратить обратно в исходный путь. R2 не восстанавливает скрытые URL из старых отчётов; для проверки конкретного документа потребуется исходная страница/ссылка от владельца сайта.

## 12. Сравнить два запуска и переоформить старый отчёт

В том же терминале после пунктов 6 и 8:

```bash
comparison_dir="$PWD/reports/compare-$(date +%Y%m%d-%H%M%S)"
pdscan compare "$report_r1/report.json" "$report_r2/r1/report.json" --output "$comparison_dir"
explorer.exe "$(wslpath -w "$comparison_dir")"
```

Здесь сравниваются два HTTP-этапа. Для двух полноценных запусков R2 используйте два корневых `report.json` от `combined`. Если терминал закрывали, переменные `report_r1` и `report_r2` потеряны: задайте их заново с фактическими путями. Команда создаёт HTML и JSON без обращения к сайту. Исчезновение проверки не считается устранением нарушения; отличающиеся версии/настройки помечаются.

Переоформление существующего отчёта без нового сканирования:

```bash
pdscan render "$report_r1/report.json" --output "$report_r1/report-new.html"
```

Отчёты схемы 1.0 из R1 читаются. Новые правовые доказательства в них не добавляются задним числом. Новые отчёты имеют схему 1.1; старый пакет может не уметь их читать.

## 13. Следующий запуск после закрытия терминала

```bash
cd ~/projects/pdscan-0.2.0rc1
source .venv/bin/activate
pdscan --version
```

Затем повторите пункт 6 или 8 с новой папкой результата. Создавать `.venv`, устанавливать wheel и скачивать Chromium каждый раз не нужно. Выход из окружения:

```bash
deactivate
```

Вернуться к прежнему R1 можно, активировав `.venv` в его старой папке. Проверяйте `pdscan --version`, чтобы понимать, какой пакет запускается.

## 14. Типичные ошибки

| Симптом | Действие |
|---|---|
| `pdscan: command not found` | Активировать `.venv`, выполнить установку wheel; проверить `python -m pip show pdscan` и `which pdscan` |
| `No such file or directory` | Проверить `pwd`, `ls`, реальную распаковку и точный путь; путь с пробелами заключить в кавычки |
| `Executable doesn't exist` / browser launch error | Выполнить установку Chromium из пункта 7 и `doctor --browser` |
| `output_exists...` / общая ошибка ValueError | Выбрать новую пустую папку отчёта; не путать путь файла и каталога |
| Серый цвет, код 3 | Открыть причины неполноты и браузерные сценарии; это не признак соответствия или нарушения |
| `unsupported` в сценарии | Кнопка не распознана однозначно; сканер её не нажимал |
| Chromium не устанавливается | R1 остаётся работоспособным; сохраните текст ошибки установки для разбора |
| `explorer.exe` не найден | Команда предназначена для WSL; используйте файловый менеджер вашей ОС |

Для сообщения об ошибке достаточно версии, `doctor --browser`, команды запуска, кода завершения и обезличенного `report.json`. Перед передачей всё равно проверьте отчёт: имена публичных хостов остаются видны.

## 15. Проверки для разработчика

Из корня исходников в активном окружении:

```bash
PYTHONPATH=src python -m unittest discover -s tests -v
```

`PYTHONPATH=src` действует только на эту команду и заставляет тесты брать текущие исходники. Интеграционный тест браузера пропускается при недоступном Chromium; `OK (skipped=1)` не означает успешную проверку браузера. Тесты используют искусственные страницы и тестовые TLS-сертификаты, не отправляют формы на реальный сайт.

Сборка wheel из исходников (для установки готового архива не нужна):

```bash
python -m pip install -r requirements.lock
python -m pip wheel --no-deps --no-build-isolation . --wheel-dir dist
```

`Dockerfile` пока относится только к R1: браузер в образ не включён; контейнерный R2 не заявлен проверенным. Матрица развития находится в `docs/SPEC_CHANGE_1_5.md`. Анализ содержания PDF/DOCX, сверка уведомления РКН и веб-интерфейс в этот кандидат не включены.
